## 一、檢索

主要語言英文、輔以中文檢索。三大主題：

1. **全球 FinTech 金融科技** — 範圍不限於 AI。涵蓋支付與清算、銀行科技、穩定幣與代幣化存款、數位資產、法遵科技、財富與保險科技、FinTech 募資與併購、監理動態。AI 相關題材優先，但當 AI 題材不足時，一般 FinTech 重要新聞同樣採用。
2. **全球 AI 金融市場動向** — AI 股走勢、財報、資本支出、算力交易、估值與融資風險
3. **全球 AI 科技應用突破與話題** — 模型發布與更新、能力突破、代理平台、產業落地、AI 資安，**以及業界正在熱議的話題**：路線之爭、爭議事件、重要研究發現、人才與資本動向、監理與政策辯論。話題型內容要有明確的一手報導支撐，不可只是評論彙編。

### 時間視窗（嚴格遵守）

先確認今天是星期幾，再決定視窗（台北時間）：

| 執行日 | 檢索視窗 |
|---|---|
| 週二 – 週五 | 執行時刻往前 **24 小時** |
| **週一** | **回溯至上週六 00:00**，完整涵蓋週六、週日 |

**視窗外的新聞一律不得採用**，即使它看起來很重要。聚合網站常把數日前的舊聞放進「本週回顧」，務必以**一手來源的實際發布日**判斷。（實例：某聚合站把 Visa 收購 BioCatch 列在 8/7 週報中，一手來源顯示實際宣布日為 8/3。）

### 則數（彈性）

每主題 **最少 3 則、最多 5 則**。品質優先於數量——視窗內只有 3 則夠格就出 3 則，不要為湊數而納入視窗外或來源薄弱的內容。

若某主題在視窗內連 3 則都湊不滿，才往前逐步擴充到剛好 3 則為止。補足的那幾則**只在卡片的日期標籤加註**（例如 `08/03 視窗外`），**不要在頁面上另寫說明段落**——產製過程的交代一律只寫在交付訊息裡。

## 二、跨日去重（重要）

同一則新聞不得在不同日期重複出現。

**做法**：產製前先讀 `history.json`，取出**日期早於今天**的 `items`（過去 30 天內），逐一比對候選新聞。

**比對範圍不含今天自己的紀錄。** 若 `history.json` 裡已有今天日期的條目，代表今天曾執行過，這是重跑——此時應正常重新產製當期內容（可沿用相同新聞），並在更新 history 時取代掉今天的舊紀錄，而不是新增重複的一份。

### 判定規則

| 情況 | 處置 |
|---|---|
| 相同 `url` | **排除** |
| 相同事件、核心事實無新增（只是換一家媒體重述） | **排除** |
| 相同事件**但有實質進展** | **可採用**，但須標示為後續報導 |

「實質進展」指出現了新的可查證事實，例如：新的數字或財務條件、監管機關介入或裁定、當事方正式回應、決策反轉（暫停→恢復）、實際交付或上線、受影響範圍擴大。單純的評論、分析或轉述**不算**進展。

### 採用後續報導時的寫法

- 標題後加註 `（後續）`
- 內文**第一個列點**必須先寫「前情」：一句話交代先前報導了什麼、哪一天
- 第二個列點起才寫今日的新增事實

### 產製後務必更新 history.json

把當期所有條目追加進 `items`，每筆包含 `date`、`topic`、`key`、`title`、`url`。`key` 為事件識別碼（小寫、連字號，格式如 `openai-astra-halt`），同一事件的後續報導**沿用相同的 key**，方便日後追蹤事件線。

同時刪除超過 30 天的舊紀錄，避免檔案無限增長。

## 三、品質要求

- **優先採用一手來源**：公司官方新聞稿、監理機關公告、原始報導。新聞聚合站僅在找不到一手來源時使用，並須於該則連結處註明。
- **交叉查證**：搜尋摘要常只反映片面事實。至少對每個主題的「3 顆星」條目做第二次查證，確認方向沒有偏差（例：某公司財報優於預期，股價卻可能因其他因素重挫）。
- **無法佐證的說法一律剔除**，不要為了湊字數保留。
- **連結必須有效且可公開存取**。付費牆來源（Bloomberg、Finextra、TheStreet 等）可作為交叉佐證，但不宜作為條目的唯一連結。
- **每則新聞都要標註一手來源的實際發布日期**。

### 連結檢查（每則都要做）

搜尋引擎常回傳**沒有日期的通用網址**，內容其實是好幾年前的。採用前逐一確認：

| 檢查 | 處置 |
|---|---|
| 網址含 `/2024/`、`/2025/` 等舊年份 | **不用** |
| 網址無日期路徑（純數字 ID 等） | 實際開啟確認發布日；開不了就**不用** |
| 滾動頁面（`/this-week`、`/latest`、`/today`） | **不可作為唯一連結**，改找永久連結 |
| 找不到合格連結 | **捨棄該則**（降到 3 則仍符合規格），不要放會失效的網址 |

實例警示：`seekingalpha.com/article/4716929-...` 的文章 ID 屬 2024 年區間；`aiagentstore.ai/ai-agent-news/this-week` 隔週內容就整個換掉。

**最優先：** 公司官方新聞稿與投資人關係頁、監理機關公告（CISA、SEC、Fed、FCA、ESMA、FSB 等）、官方技術部落格（AWS、NVIDIA、Google、Meta）。

### 中文檢索：只當線索，不當引用

中文財經快訊（金十數據、新浪科技、華爾街見聞等）的**發稿速度與亞洲時段覆蓋優於英文來源**，實測確實撈到過英文檢索漏掉的重大新聞。**每期都要做一輪中文檢索**，別跳過。

但這些站有兩個硬限制：

- **金十數據首頁是 JS 動態渲染，WebFetch 抓不到任何內容**；個別快訊也沒有穩定的永久連結。
- 內容多為轉載外電，本身不是一手來源。

因此規則是：**中文快訊用來發現題材，引用時必須回溯到可驗證的英文一手或主流來源**，絕不直接掛中文快訊站的連結。若回溯不到合格來源，該則就捨棄。

（實例：2026/08/12 那期由中文檢索發現「NVIDIA 聯手華爾街 5,000 億美元 AI 基礎設施融資」，回頭以 CNN、CNBC、Fortune 查證後採用，補上了英文檢索的缺口。）

## 四、內容格式

全文繁體中文（英文專有名詞、公司名、產品名保留原文）。每則新聞：

- **標題**：星等 1–3 顆代表重要性，每個主題內由高至低排列
- **日期標籤**：一手來源的實際發布日（`MM/DD`）
- **內文**：4 個列點，全則合計約 150–200 字
- **連結**：完整 URL，顯示文字為來源名稱

每主題結尾附 100–150 字總結，做趨勢判讀而非條列重複。

開頭必須保留免責聲明區塊。

## 五、發布前除錯（必做，不可跳過）

寫完 HTML 後、發布前，**把檔案整份讀回來**逐項核對。以下每一項都是實際發生過的錯誤，不是假想情境。

### A. 連結稽核

逐條檢查每個 `href`：舊年份（`/2024/`、`/2025/`）→ 換掉；無日期路徑的純數字 ID → 實際開啟確認，403 就不用；滾動頁（`/this-week`、`/latest`）→ 找永久連結；連結數必須等於卡片數。找不到合格連結就刪除該則，則數降到 3 則仍符合規格。

### B. 內容查證

- **敘述方向有沒有反了**（實例：SpaceX 財報優於預期，股價卻重挫 14%）
- **有沒有把 A 說成 B**（實例：曾把 Agent Plugins 寫成「與 MCP 競爭」，實際是疊在 MCP 之上的封裝層）
- **日期是不是聚合站給的**（實例：聚合站把 8/3 的 Visa 收購案列進 8/7 週報）
- 每個具體數字都能在來源中找到

### C. 結構完整性

卡片總數 = 三主題則數總和；每主題序號連續且從 01 開始；每張卡片具備 rank／seq／date／h3／ul／連結；三個 topic section、三個 summary；`.disclaimer` 只有一段；無未定義的 CSS 變數。

> **批次編輯警告**：用字串定位刪除卡片時，錨點極易抓到前一張卡片的開頭。（實例：刪 A 卡時連同前面的 B 卡一起被刪；另一次想刪流程說明卻刪掉了免責聲明。）每次批次刪改後**必須重數卡片數與標題清單**。

### D. 一致性

masthead 的「共 N 則」與實際相符；各主題總結提到的新聞都還在（刪某則後總結常忘了改）；無上一期殘留；無錯字或混入其他語系字元（曾誤打韓文「창」而非「創」）。

### 發布後

用 WebFetch 開啟固定網址，確認頁面確實是當期內容。若抓到舊內容代表發布沒生效，要重試。

## 六、發布

以 `brief.sample.html` 為範本，替換當期內容。**版面、CSS、配色、深淺色主題全部原封不動沿用**，只換文字與連結。

呼叫 Artifact 工具時**務必帶 `url` 參數**指向既有頁面，否則會產生新網址：

- `url`：`https://claude.ai/code/artifact/a24ac88f-9191-44a9-af47-47808d523f6b`
- `favicon`：`📰`（固定不變）
- `label`：當日日期
- `description`：一句話描述當期重點

**若遇到 409 衝突**（另一個 session 已發布更新版本）：先 WebFetch 讀回線上版本比對，確認自己的內容確實較新且沒有蓋掉別人的成果，再重新發布。**不要直接用 force。**
